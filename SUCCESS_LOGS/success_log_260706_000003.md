# Success Log 260706_000003

## Status

VERIFIED SUCCESS

## Task

Apply the pixel-based transform box system across the active Transfork tools.

## Problems

- Click-and-hold during sprite dragging caused a small visual size increase.
- Resize and rotate activation could make the transform box larger.
- The alpha control was being treated like a resize control.
- Tool rectangles were not all using the same pixel-bound source.

## Root Cause

Pixel bounds still had artificial padding in shared and tool-specific paths.

The active transform preview also added extra box growth.

Handle detection was too broad because it used cursor behavior instead of only the intended transform handle icons.

## Winning Approach

- Remove artificial padding from `pixelBounds.js`.
- Remove extra growth from `snapshotToolsPixel.js` transform preview math.
- Use `api.pixelBounds.rect()` as the shared pixel rectangle source.
- Ignore `#transform-alpha-container` in transform handle detection.
- Detect resize and rotate tools by explicit handle icons.
- Bump the loader cache.

## Files Modified

- `Transfork/pixelBounds.js`
- `Transfork/snapshotToolsPixel.js`
- `Transfork/TransforkLoader.user.js`

## Reusable Engineering Rule

All transform tools must share one pixel-bound rectangle source.

Do not let each tool invent its own bounding box.

Do not route tools by generic cursor style when normal UI controls can share that cursor.
