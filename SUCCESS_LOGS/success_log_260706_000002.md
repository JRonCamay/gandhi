# Success Log 260706_000002

## Status

Implementation logged after user request. Awaiting final user verification before treating as a fully confirmed success pattern.

## Task

Fix Transfork transform release problems after snapshot-based operations.

## Problems

- During sprite drag mode, the sprite briefly disappeared and reappeared on mouse release.
- When resize or rotate tools activated, the transform box became bigger than the pixel-tight sprite bounds.
- Resized sprites restored to a previous size when horizontal or vertical flip was pressed.

## Root Cause

Multiple transform operations were transitioning between snapshot overlays and the real Scratch drawable too abruptly.

The snapshot node was removed immediately after restoring the real sprite, which exposed a short redraw gap.

Resize and rotate preview box calculations used internal source dimensions and added extra growth, which caused the visual transform box to become larger than the active pixel bounds.

Flip operations changed direction and visual flip state without preserving the current drawable scale reliably.

## Failed Approaches

- Allowing snapshot overlays to be removed in the same frame as real sprite restoration.
- Calculating transform preview bounds from raw internal canvas size instead of the displayed pixel rect.
- Letting flip logic depend on Scratch direction/size state without explicitly restoring drawable scale.

## Winning Approach

- Restore the real sprite first.
- Delay snapshot removal by two animation frames so the real drawable is already visible before the overlay disappears.
- Calculate transform preview bounds from the current on-screen pixel rectangle.
- Preserve drawable scale when applying horizontal or vertical flip.
- Bump the loader cache so the browser fetches the updated modules.

## Why it Worked

The visual handoff becomes continuous: the snapshot stays visible until the real drawable has time to redraw.

The box uses one visual coordinate system: the current pixel rect on screen.

Flip no longer accidentally reverts scale because the active drawable scale is captured and restored around the flip operation.

## Files Modified

- `Transfork/snapshotDragPixel.js`

## Reusable Engineering Rule

For snapshot-to-real transitions, restore the real drawable first and remove the snapshot after the next redraw window.

For transform previews, calculate from the current visual pixel rect, not from raw internal source dimensions.

For flip operations, preserve drawable scale explicitly.

## Applicable Future Tasks

- Snapshot drag release
- Resize preview

- Flip operations
- Any feature that hides the real sprite and shows a temporary snapshot
