# Success Log 260706 120000

## Task

Rebuild Transfork resize and rotate execution as the main transform system instead of continuing small patches.

## Problem

Transform tools were difficult to maintain because resize, rotate, preview, commit, renderer wait, measurement, compensation, and cleanup behaved like independent event bodies.

Symptoms included:

- Sprite jump after transform release
- Rotation compensation using stale renderer state
- Occasional preview stutter
- Duplicate ownership between older resize/rotate modules and the newer snapshot pipeline
- Hard debugging because multiple handlers could run in uncertain order

## Root Cause

The system was event-driven instead of process-driven.

Handlers decided independently when to act. Scratch renderer updates are not perfectly synchronous, so final pixel measurement could happen before Scratch finished updating the drawable.

## Failed Approaches

- Static pivot offset compensation
- Per-frame scaled/rotated pivot compensation
- Release-only center compensation without strict sequencing
- Disabling old resize/rotate modules helped isolate ownership, but did not create a maintainable architecture by itself

## Winning Approach

Use the Sequenced Transform Factory Line.

The transform system now has two lanes:

### Main Sequence

Controls lifecycle and async ownership handoff.

```text
0  IDLE
1  WAIT_START_STABLE
2  CAPTURE_SNAPSHOT
3  HIDE_REAL_SPRITE
4  ENTER_PREVIEW
5  PAUSE_FOR_FRAME_LOOP
6  STOP_FRAME_LOOP
7  APPLY_FINAL_TRANSFORM
8  WAIT_COMMIT_STABLE
9  MEASURE_FINAL_CENTER
10 COMPENSATE_FINAL_CENTER
11 WAIT_COMPENSATE_STABLE
12 RESTORE_REAL_SPRITE
13 REMOVE_SNAPSHOT
```

### Frame Sequence

Controls one preview frame.

```text
100 IDLE
101 READ_INPUT
102 COMPUTE_PREVIEW
103 DRAW_SNAPSHOT
104 DRAW_BOX
```

Mousemove only records the latest input. requestAnimationFrame owns preview rendering.

Commit waits for Scratch to become stable before measuring and compensating.

## Why it Worked

Only the active sequence stage can execute.

This removed overlap between handlers and made resize/rotate behave like a factory line:

```text
input -> preview -> commit -> wait -> measure -> compensate -> restore
```

The renderer is explicitly allowed to finish before pixel measurements are trusted.

Preview became smoother because mousemove no longer performs full immediate redraw work.

Debugging became easier because the current execution point is visible through sequence state instead of hidden inside nested event handlers.

- `Transfork/snapshotToolsPixel.js`

## Files Retired

- `Transfork/resize.js`
- `Transfork/rotate.js`

These modules were removed from the active loader. Their old implementation bodies were replaced with inactive marker comments because repository deletion was blocked by the available tool path. They no longer register modules or own runtime behavior.

## Reusable Engineering Rule

When a feature has preview state, real state, async renderer updates, and final commit cleanup, do not let event handlers run independently.

Create a sequenced factory line:

```text
One sequencer owns time.
Workers own behavior.
```

Use a main lifecycle lane for async handoff and a frame lane for per-frame preview.

## Applicable Future Tasks

Use this pattern for:

- Transform tools
- Canvas/DOM preview tools
- Sprite editing systems
- Drag/resize/rotate pipelines
- Any project where real state and preview state can drift
- Any project where final measurement depends on an async renderer or UI update
